# Сбор данных для поиска платёжных задач

Сначала сохраняем наблюдения, затем проверяем отдельные гипотезы. Порог интерфейса,
возраст версии, отсутствие жалоб или сомнительная трактовка показателя не являются
причиной удалять исходные данные. Цель — находить задачи, за решение которых можно
получить деньги, включая бесплатный продукт с измеримой воронкой в платный.

## Три разных слоя

1. **Наблюдения:** что вернул конкретный источник, когда, для какой страны и
   запроса. Сохраняются ошибки, пустые ответы, неизвестные значения и ограничения.
2. **Вычисления:** воспроизводимые метрики с версией метода и датой расчёта. Сырые
   значения не заменяются новым выводом. Один и тот же корпус пригоден разным гипотезам.
3. **Решение:** боль, покупатель, преимущество, канал и экономика. Наблюдения
   конкурентов порождают кандидата; собственный эксперимент проверяет заработок.

Реестр проверяемых вопросов: `research_hypotheses.json`. Старые версии, обновляемые
продукты с жалобами, маленькие платные инструменты, локальные задачи, вход в чарт
и бесплатная воронка — разные гипотезы с разными необходимыми доказательствами.
Искать все их одним составным score нельзя без валидации на реальных исходах.

## Что сохраняется

| Наблюдение | Где | Ограничение |
|---|---|---|
| Все карточки, вернувшиеся в поиске, включая 0–499 оценок | `snapshots`, история в `niches.db.gz` | Выдача ограничена запросами/странами/лимитом; это не весь магазин |
| Последняя проверка письменных отзывов | `demand` | Это заменяемый кеш для интерфейса |
| Накопительные проверки, включая EMPTY/ERROR | `demand_samples` | С момента внедрения; сохранившиеся старые проверки импортируются с исходной датой |
| Признаки приложения на момент проверки | `demand_samples.snapshot_json` | Только наблюдение не позднее RSS; если его нет, контекст неизвестен |
| Исходы зафиксированного исследования | `study_members`, `study_reviews` | Старая когорта не переписывается новым сбором |
| Полные HTTP-ответы локальных сборов | `.data/raw/objects`, индекс `.data/raw/index.sqlite3` | Только при запуске через `collect.py`; вне Git, только на этом компьютере |
| Политика разведки и связь с исходным ответом | `collection_policy`, `raw_ref_json` | У старых записей политика и полный ответ неизвестны |

`demand_samples` сохраняет даты, оценки, известные ID и версии отзывов, а также
результат/метод проверки. Тексты и дополнительные поля поиска доступны в полном
локальном ответе: описание, release notes, языки, ограничения ОС, жанры, доступные
поля монетизации и прочее, что фактически отдаёт API. Отсутствующее поле остаётся
неизвестным. Нельзя восстановить перезаписанные старые HTTP-ответы или тексты по
датам и оценкам. Цена бесплатной загрузки не означает отсутствия подписки/IAP;
цена платной загрузки не подтверждает продажи.

Архив сохраняет точные байты тела HTTP-ответа, URL, время получения, статус,
безопасный набор заголовков и SHA-256. Одинаковые тела занимают один сжатый объект,
но каждый запрос получает отдельное событие. Сохраняются также тела ошибочных
HTTP-ответов; сетевой сбой без ответа остаётся ошибкой в журнале сборщика.
Секретные заголовки и Telegram не архивируются. Ссылки на объекты относительные:
другому компьютеру нужен сам локальный архив, одного `raw_ref_json` недостаточно.

Повторные RSS-срезы перекрываются. Для числа новых отзывов нельзя суммировать
страницы: нужны ID в пределах приложения/страны и отдельный учёт редактирования
отзыва. Дата RSS может означать обновление отзыва, а не его первую публикацию.
Если в старом срезе ID неизвестен, уникальность не считается установленной.

## Широкая разведка без роста бюджета запросов

Ежедневный/слотовый дополнительный бюджет остаётся **до 20 RSS на страну**:

- до 10 — существующая разведка обновляемых версий с ≥500 оценок;
- до 10 — широкая разведка текущих поисковых карточек по размеру (0–49,
  50–499, ≥500), возрасту версии (<12, 12–18, ≥18 месяцев, неизвестно) и цене
  загрузки (free/paid/неизвестно), с ротацией поисковых направлений.

Один app×country не проверяется дважды в этих двух частях. Обычно действует
пауза 7 дней, после ошибки — 1 день, новая версия разрешает перепроверку раньше.
Старые и новые проверки чередуются. Выбор широкой части не зависит от числа
жалоб или оценки результата. Политика `wide-v1:...` сохраняется вместе с проверкой.
Эта небольшая ротационная разведка не является случайной выборкой пользователей,
не взвешивается по объёму рынка и не меняет научный контроль прошлого исследования.
Установка новой квоты не означает, что все страны уже были по ней проверены.

Связь, найденная после просмотра архива, считается разведочной гипотезой. Для
подтверждения заранее фиксируем её определение и проверяем на следующем окне или
отложенной выборке. При множестве сравнений учитываем множественные проверки;
выбирая лучший результат из сотни графиков, нельзя выдавать его за независимое
подтверждение. По возможности используем доверительные интервалы с группировкой
по приложению и публикуем также отрицательные результаты.

Порог 500 остаётся фильтром текущей продуктовой очереди. Все наблюдения ниже порога
доступны для отдельной гипотезы, их число и охват видны в качестве данных. Перед
построением доли/корреляции нужны явные знаменатель, пропуски, усечение RSS,
источник, окно времени, зависимость стран одного приложения и способ отбора.

## Бесплатное хранение и границы

Новые платные сервисы не используются. Для локального архива установлен предел
**5 GiB сжатых объектов и индекса**. При заполнении сбор останавливается с ошибкой;
история автоматически не удаляется. Предел можно явно увеличить при наличии места.
Архив не является резервной копией: потеря этого диска потеряет полные ответы.
Парсированная история продолжает храниться в контрольной точке репозитория.

В GitHub Actions новые `demand_samples` сохраняются в контрольной точке, но полный
сырой архив **не включён**: диск раннера временный. Считать Actions artifacts
бесплатным бессрочным хранилищем нельзя: [объём](https://docs.github.com/en/billing/reference/product-usage-included)
и [срок хранения](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts) ограничены.
Рабочая БД сжимается; существующий предел 90 MiB защищает от лимита GitHub файла.
При росте нужно измерить объём и вынести старые контрольные точки на свой диск
или другое уже имеющееся хранилище. Это отдельный шаг, не скрытая новая подписка.

Расширять запросы до 200 результатов имеет смысл для отдельных усечённых выдач;
сначала сравнить дополнительные уникальные релевантные карточки на запрос и
объём хранения. Google Play, Reddit, Telegram, страницы цен и интервью нужны
точечно для конкретной гипотезы; они не объявляются собранными автоматически.
Публичный рассказ о выручке остаётся рассказом, пока не ясны период, комиссия,
расходы, источник трафика и возможность проверки. Даже подтверждённый чужой кейс
не оценивает вероятность успеха нового продукта без учёта неудачных запусков.

## Практические команды

```bash
# Полный ответ каждого локального поискового запроса + обычные наблюдения.
python3 collect.py scanner --countries us --categories construction --no-alerts

# Широкая разведка: отдельная команда с общим бюджетом до 20 на страну.
python3 collect.py demand_check --explore-updated 10 --explore-wide 10 --countries us --delay 3

# Тексты и полные ответы для проверки боли конкретного кандидата.
python3 collect.py review_clusters --ios 1494386815 --country us --days 90 --out /tmp/candidate-reviews.json

# Импортировать только сохранившиеся старые измерения; идемпотентно.
python3 demand_history.py --seed-existing
python3 demand_history.py
python3 raw_archive.py
```

При новом денежном эксперименте заранее фиксируем аудиторию, предложение, канал,
цену, горизонт, допустимую стоимость привлечения и критерий отказа. Считаем
собственные чистые поступления, возвраты, затраты, удержание и атрибутируемые
переходы между приложениями. Сценарные параметры остаются предположениями, пока
их не заменят данные именно этого запуска.
