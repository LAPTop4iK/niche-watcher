# HANDOFF / АРХИВ ПРОЕКТА «NICHE WATCHER»

Документ для верифицирующего агента: полная сводка задачи, требований заказчика,
принятых решений, построенной системы и чек-лист проверки. Дата: 2026-10-31.
Верификатору: каждый пункт проверяем командами из раздела 8; каждая цифра в отчётах
трассируется до ответа публичного API (iTunes Search/Lookup/RSS, google-play-scraper).

## 1. Цель проекта (актуальная формулировка заказчика, 2026-10-31)

**Найти нишу, где можно построить прибыльное приложение на базе конкурента
(лучше/симпатичнее/дешевле) или по другой модели портфеля входа (README §16) —
и делать это на системе доказательств, а не интуиции.** Беларусь в цели не входит
(исторический старт разговора, закрыт и вычеркнут). Требования заказчика по ходу:

1. [ИСТОРИЯ, закрыто] старт с анализа p2p-шеринга вещей в Беларуси — не входит в текущую цель.
2. Разобрать модель «заходить на рынки, где конкуренты сдают позиции, а спрос есть»
   (история про «калькулятор цемента») и выстроить **систему** поиска таких ниш.
3. Цель-стратегия (ГЛАВНАЯ): взять лидера ниши → разобрать его механики (IPA) → собрать
   своё приложение лучше/симпатичнее → играть на цене.
4. Мульти-рыночность: «в США одни топы, в Японии другие, там тоже есть деньги» —
   покрыть гибким конфигом с формулами.
5. Найти все «хорошие экономики и аномалии заработка», включая малые богатые рынки.
6. Найти аналоги (платные сервисы), понять что упускаем мы / что упускают они;
   тренды-2026 покрыть формулами; исключить ошибки выжившего.
7. Учёт роста конкуренции в нише (не только decay, но и heat/приток).
8. Regional arbitrage: приложение популярно в одном рынке, аналога нет в другом.
9. Проверить валидность всех формул и метрик (нет ли выдуманных корреляций).
10. Инфраструктура: git/GitHub Actions автоматика, красивые чарты на вебе,
    Telegram-алерты, без VPS; weekly-прогон разбить по дням (не влезал в таймаут).
11. Автоматизация мониторинга делистингов/освобождающихся ниш; веб-рынок как альтернатива.

## 2. Отказы и границы (важно для верификации этики)

- Дважды отказал в поиске/эксплуатации уязвимостей платных сервисов (paywall-bypass,
  «tier: premium одним ответом»): несанкционированный доступ, проверка = эксплуатация,
  white-hat требует авторизации/scope. Предложены легальные пути (VDP/bug bounty,
  письма вендорам, открытые датасеты, бесплатная добыча из собственных данных).
- Реверс-инжиниринг IPA заказчика лидера: рамки прописаны (README §6) — статический
  разбор своего легально полученного файла (Info.plist, entitlements, frameworks,
  локализации, строки) разрешён; снятие FairPlay (DMCA §1201), копирование кода/ассетов,
  дёрганье чужого бэкенда — нет. Инструмент REA доступен в рабочем ZCode-окружении.
- Точная история про «калькулятор цемента» не найдена; найден живой эквивалент:
  Concrete Calculator Plus (26 337 оценок, версия 2024-03) — см. раздел 5.

## 3. Хронология и ключевые решения

| Фаза | Что сделано |
|---|---|
| 1. Стартовая задача | Ресерч p2p-шеринга в Беларуси: главный блокер — ст. 12.7 КоАП (незаконное предпринимательство при систематической сдаче вещей) + отсутствие escrow/самозанятости. Легальный формат — обмен (barter), не аренда. |
| 2. Прецедент | tabletopswap.io разобран: инди-соло, ~6 недель, 2 оценки в App Store — «успех» рано объявлять, но модель (обмен без денег) юридически и инфраструктурно переносима в РБ. |
| 3. Система поиска | Зомби-модель: инкумбент гнил (версия >18 мес), аудитория жива (оценки, velocity, свежие отзывы). Написан scanner.py (iTunes Search API), БД, скоринг, алерты. Найден живой кейс: Calculator for iPad — 61 146 оценок, 71 мес без обновлений, свежий отзыв за сентябрь 2026. |
| 4. Правила платформ 2026 | Apple Xcode 26 SDK с 28.04.2026; Play target API 36 с 31.08.2026 (existing ≥35) — «конвейер зомби» систематичен; zombie crackdown Google с 07.2024. |
| 5. Мульти-рынок | markets.json: 24 гео (lang, eCPM, paid/sub affinity, CPI, tier), локализованные запросы на 14 языках, revenue_model.py (RPD/LTV/break-even CPI, сравнение 4 моделей). Вывод: US→подписка, JP→разовая покупка (уникально), DE/TW→смешанно, RU→портфель. |
| 6. Малые богатые рынки | Слоты tier-2: CH/AT/NL/FI/FR, NO/DK/SE/IE/NZ/SG, SA/AE/IL/HK, KR/RU. Аномалии: религиозные подписки SA/AE (подтверждено зомби-чётками 5,5 года гнили), язык-монополии (иврит/финский), de-локализация открывает 3 рынка. |
| 7. Аналоги | Sensor Tower поглотил AppMagic (05.2026). Наши краники: decay как измерение (у аналогов — keyword-метаданные), длинный хвост (27–33% зомби vs 3–13% в чартах — доказано на 3,8k+ приложений), бесплатность (официальные API/RSS), кластерный decay (31% соседей Calculator for iPad гнилые). |
| 8. Тренды-2026 | RevenueCat 2026: hard-paywall 10,7% vs freemium 2,1%; 69% подписочной выручки у приложений до 2020 (деньги у старых инкумбентов); AI-приложения +41% выручки/платящего, churn +30%; триалы 17+ дней конвертят +70%; 7× рост запусков (вайбкодинг). Добавлены категории ai_tools, widgets_watch. |
| 9. Heat + native-risk | Рост конкуренции в нише (fresh%, приток); матрица решений decay×heat. Флаг ⛔натив (поглощение боли ОС): framework «смерть поддержки vs смерть боли», кейс Calculator for iPad (нужна отстройка: Apple Pencil, Math Notes-гэпы). Пойман собственный баг: «concrete» ошибочно в native-списке — убран. |
| 10. Гэпы и валидность | geo_gap.py (региональный арбитраж, 28 кандидатов; пойман и починен false-positive: нерелевантные гиганты в длинных запросах → фильтр токен-пересечения). ## 6. Этические/юридические рамки (применявшиеся consistently)

- Зомби-модель структурно исключает ошибку выжившего (ищем заброшенные, а не успешные).
- Натив-флаг обязывает проверять «поглотила ли ОС боль» (фонарик — скип; бетон — нет).
- Разбор лидера — только поведенческий/метаданные/свой трафик/статика без DRM-обхода.
- Никаких обходов платных сервисов; публичные страницы проверены (403/404) и оставлены.

## 7. Известные ограничения (README §15/§17 — полные списки)

1. inflow раздувается расширением seed (тренды валидны при фиксированном seed);
2. малые выборки tier-2 (биномиальные ДИ ±13 п.п. при n=55; матрица режет n<8);
3. rating_count кумулятивен — текущий спрос = velocity + свежесть отзывов;
4. decay и heat анти-коррелированы механически (одна переменная) — один сигнал;
5. downloads ≈ ratings × 40 имеет разброс ×2.5 → деньги для ранжирования, не абсолюты;
6. affinity-множители — гипотезы до калибровки первым релизом;
7. Search API видит топ-50 ниши; делистнутые невидимы (консервативно);
8. velocity требует ≥2 прогонов ≥7 дней; Apple батчит отзывы;
9. geo-gap: вакуум ≠ спрос (проверка Trends/форумами перед go).
