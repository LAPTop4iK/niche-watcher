# Niche Watcher

Поиск и проверка гипотез для **заработка на приложениях**. Два входа: реальные боли
и рыночные паттерны. Бесплатный продукт допустим как измеримая воронка в платный.

Система ищет свежую активность старых версий и жалобы на обновляемые продукты.
Основная очередь показывает оба направления с явными основаниями и охватом RSS. Она **не измеряет выручку конкурентов и не предсказывает прибыль замены**.
Перед разработкой нужны покупатель, преимущество, канал привлечения и проверка оплаты.

## Установка и запуск

Для App Store, отчётов и дашборда достаточно Python 3.9+ и стандартной библиотеки.
В Git лежит указатель `niches.db.checkpoint.json`, сам слепок базы хранится в GitHub
Release `data-checkpoints`. Рабочая `niches.db` скачивается и восстанавливается
автоматически, если отсутствует; существующая база никогда не заменяется архивом. После
`git pull` выполнить `python3 db_store.py sync`, чтобы объединить новые и локальные
наблюдения. Слепки публикует только CI; вручную они не коммитятся.

Для дополнительного Google Play-источника: `python3 -m pip install -r requirements-play.txt`.

```bash
# Полный поиск: 24 страны, текущий набор seed; примерно 2 часа с лимитом Apple.
python3 scanner.py --all-markets --run-id my-full-scan --skip-reviews --no-alerts

# Продолжить после обрыва: та же команда, ID и конфигурация.
# Успешные запросы повторно не отправляются.

# В другой консоли — проверка отзывов по мере поступления кандидатов.
python3 demand_check.py --follow-run my-full-scan --controls 20 --workers 2 --delay 1.5

# После завершения поиска: зафиксировать сравнение и дозаполнить контроль.
python3 study_sample.py --run-id my-full-scan --fill-missing

# Проверка всей БД и обязательного завершения конкретного прогона.
python3 validate_data.py --require-run my-full-scan

# Все отчёты и интерфейс из одного согласованного снимка, без сети и сообщений.
python3 rebuild_reports.py --require-run my-full-scan
python3 -m http.server 8765 --bind 127.0.0.1 --directory dashboard

# Быстрая проверка отдельной гипотезы.
python3 scanner.py --categories construction --countries us --no-alerts
python3 review_clusters.py --ios 1494386815 --country us --days 90 --out /tmp/candidate-reviews.json

# Ограниченная разведка обновляемых версий и широкой выборки (не контроль исследования).
python3 demand_check.py --explore-updated 10 --explore-wide 10 --countries us,de --delay 1.5

# Локальный сбор с сохранением полных ответов, включая тексты и пока не используемые поля.
python3 collect.py scanner --countries us --categories construction --no-alerts
python3 raw_archive.py
```

Наблюдения не отбрасываются из-за текущей гипотезы. История RSS накапливается в
`demand_samples`; полный локальный архив хранится отдельно от Git, с пределом 5 GiB.
Облачный сбор сохраняет разобранную историю, но не полные HTTP-ответы. Что собираем,
что пока неизвестно и как проверяем заработок: [стратегия данных](docs/data_strategy.md)
и [реестр гипотез](research_hypotheses.json). Новых платных сервисов нет.

`--run-id` нельзя повторно использовать с другими запросами, странами или лимитом.
Новый ID начинает новое наблюдение. Каждый запрос сохраняется отдельно, поэтому
пустой ответ, ошибка и отсутствие запроса различаются. Частично завершённый прогон
не получает статус COMPLETE и завершает команду с ошибкой.

Во время записи БД не делать checkout/rebase/stash её рабочего файла. Сканеры
одной базы защищены файловой блокировкой. Для копии живой SQLite использовать
`sqlite3.Connection.backup`; файл вместе с журналом не копировать обычным `cp`.

## Что означают сигналы

| Сигнал | Значение | Чего не доказывает |
|---|---|---|
| Старые версии | Версия ≥18 месяцев, локальных оценок ≥500 | Уход автора, поломка, доступный рынок |
| Более свежие версии с жалобами | Версия <18 месяцев, ≥500 локальных оценок, свежий RSS; на текущем выпуске ≥3 разных отзыва 1–2★, их доля выше базы категории×страны со сжатием, тема повторяется; поисковая запись — только со словами запроса в названии | Решаемую боль и готовность платить |
| ALIVE | ≥2 письменных отзыва за 90 дней (`rss`) либо прирост оценок сверх шума счётчика (`velocity`). Периоды сравнивать внутри одного пути | Оплаты или готовность перейти |
| WEAK | Один свежий письменный отзыв | Достаточный объём рынка |
| UNKNOWN | Нет пригодных данных, ошибка, пустой или устаревший RSS | Мёртвый спрос |
| NO_RECENT_EVIDENCE | В пригодном наблюдении нет свежего сигнала | Смерть самой ниши |
| Velocity | Одна страна, база ≥6,5 дня и ≤45 дней; значение скана — максимум по запросам, база — наибольшее значение до неё, шум max(2; 0,1%); блокируют конец ниже базы и два падения | Установки, продажи или устойчивый тренд |
| Низкие свежие оценки | 1–2★ в датированной выборке | Реальную поломку или платёжный спрос без чтения текста |

Порог двух отзывов — исследовательское допущение. В `docs/hypotheses.md` есть
чувствительность к порогам 1/2/5/10, сравнение с обновляемыми приложениями и
ограничения выборки. RSS ограничен последними примерно 50 отзывами; R90 — нижняя
граница. Повторные страны одного приложения не являются независимыми наблюдениями.

В `seed_queries.json` включены 25 из 25 поисковых направлений. Это наш набор тем,
не все категории App Store и не полный охват рынка. Базовый прогон 31 октября
охватил 23 направления; отдельное расширение 1 ноября проверяет fitness_calc и
boardgames (160 запросов по 24 странам).

Категории берутся из поисковых запросов. Название и общий ключевой токен не
подтверждают релевантность задаче. Наблюдения чартов и ссылок со страниц App Store не
ранжируются как самостоятельные продуктовые ниши. Завершённый пустой SERP удаляет
историческое приложение из текущего состава этого запроса. Ссылки со страницы
могут включать портфель автора и рекомендации; они не образуют проверенный граф
похожих продуктов. Ошибка Google Play не меняет состав App Store.

## Интерфейс и отчёты

- `dashboard/`: фильтры по стране, категории, активности, цене и свежим 1–2★;
  объединение стран одного приложения; основания и неизвестные; сценарий экономики;
  журнал полноты и статус проверки гипотез.
- `report.md`, `demand_report.md`: кандидаты и свежая активность.
- `docs/scoreboard.md`: очередь исследования без составного profit score.
- `geo_gap_report.md`, `docs/divergence.md`: описательные различия; не доказательство
  свободного рынка, миграции спроса или реальной позиции на устройстве.
- `docs/hypotheses.md`, `docs/current_metrics.json`: воспроизводимые проверки.
- [Итог полного перепрогона](docs/VALIDATION_2026-11-01.md): область, результаты и ограничения.
- [Кейсы инди-разработчиков](docs/INDIE_EVIDENCE.md): первичные источники и уровень доказательств.
- [Первый аудит](docs/AUDIT_2026-10-31.md) и [HANDOFF](HANDOFF.md): решения и ограничения.

## Экономика и бесплатная воронка

```bash
python3 revenue_model.py --geo us --model sub --horizon 6 --conversion .02 --churn .15 --refund .03 --cpt .50 --cost-per-active-day .002
python3 revenue_model.py --geo us,de --model sub --requirements --rank 3 --target 1000
python3 calibrate.py --installs 1200 --ratings-gained 38 --paying 41 --revenue 87.40 --matched-cohort
python3 revenue_model.py --observed
```

Модель — сценарий, не прогноз. `paid` означает разовый unlock после бесплатной
установки, не платную загрузку. Реклама считается за D0–D30, подписка — за заданное
число месяцев при постоянном оттоке. Горизонты нельзя смешивать при выборе модели.
Affinity стран не участвует в расчёте. Фактические данные за период сохраняются
через `calibrate --apply` с метаданными приложения, страны, модели и периода;
они не превращаются автоматически в когортный LTV. Без `--matched-cohort` отношения
периодных итогов не называются конверсией или ARPU: платящие могут относиться к
другим установкам. Флаг допустим только для действительно совпадающей когорты.

Для бесплатного продукта считать **дополнительные** оплаты вашего платного продукта
и чистый вклад этих покупателей за вычетом разработки, поддержки и привлечения.
Атрибуция переходов и причинный эффект — разные проверки.

## Telegram и автоматика

Секреты: `TG_BOT_TOKEN`, `TG_CHAT_ID` в GitHub Actions; значения в репозиторий не писать.
`python3 tg_digest.py --print` показывает сообщение без отправки.
`python3 tg_setup.py` проверяет бота и находит новый чат; тестовое сообщение требует
явного `--send-test`. Чтение getUpdates само по себе не подтверждает обновления offset.

Уведомления сохраняются в очереди до подтверждения Telegram. Сбой оставляет их для
повторной попытки; при потере ответа после фактической отправки возможен повтор.
Настроенные ошибки доставки видны в результате запуска. Наличие секретов само по
себе не доказывает доставку нового формата.

Изменяемая SQLite не отслеживается Git. Слепок без производных индексов сжимается в xz,
получает имя по SHA-256 и загружается в Release раньше, чем указатель попадает в Git,
поэтому коммит данных не добавляет бинарный файл, а указатель не ссылается на пропавший
слепок. Хранятся 30 последних слепков, каждый содержит всю историю. Предел актива 2 GiB.
Если Release недоступен, слепок один раз идёт в Git как `niches.db.xz`, следующее успешное
сохранение возвращает указатель. Скачивание идёт без токена: репозиторий должен быть публичным.
CI сохраняет рабочую копию вне checkout до любых Git-операций, объединяет исходы
параллельных записей и пересобирает отчёты. Изменение кода upstream требует нового
запуска; данные при ошибке сохраняются в recovery-artifact на 7 дней, если шаг
сохранения успел выполниться. Жёсткое исчезновение runner до сохранения не покрыто.
Для локального хранилища слепков задайте `NICHE_CHECKPOINT_DIR`.

Actions сериализует сканы через concurrency с `queue: max`. Изменения БД и отчётов
сохраняются и при ошибке последующего шага. `db_merge.py` переносит наблюдения,
проверки спроса, журнал запросов и очередь уведомлений; SENT не откатывается в PENDING.

## Чистая проверка без удаления истории

[Проверка расширенного кода и публикация](docs/research_pipeline_verification.json):
59 тестов, чистый replay, матрица 48 запросов по 24 странам и 25 направлениям.
[Предыдущая проверка базового кода](docs/PIPELINE_VERIFICATION_2026-11-01.md) сохранена отдельно.

`python3 verify_pipeline.py --live` пересобирает все наблюдения завершённого
поискового прогона в пустой временной базе, сравнивает содержимое и результаты
гипотез, проверяет продолжение без дублей. Это offline replay сохранённых полей,
не повторная загрузка всех HTTP-ответов.

Затем выполняется отдельная живая матрица: один запрос на страну и один на каждую
активную категорию, до 10 результатов; она не смешивается с рабочими наблюдениями.
В Actions ручной `mode=verify` дополнительно проверяет Telegram через getMe/getChat
без отправки сообщений и публикует Pages только после успеха проверки.
Ручной `mode=scan` сохраняет обычный tier-1 сбор.

В дашборде источник выбирается отдельно: поиск, чарты, ссылки или вся база.
Сводка и категории относятся к выбранному источнику. Telegram содержит одну ссылку
«Открыть дашборд»; голые имена файлов в сообщения не вставляются.

## Формат уведомлений после скана

Один скан с новыми объектами даёт одну короткую сводку: общее число app×страна,
до шести примеров без рангов и одна ссылка на дашборд. Это объекты для проверки,
не топ доходности. Уже отправленные объекты не включаются заново из-за изменения
порядка или размера пачек; старые записи outbox учитываются. Время указано по
Варшаве. Pages публикуется после успешных плановых сборов; уведомление может
опередить публикацию на несколько минут. [Разбор случая 12+6](docs/TELEGRAM_DELIVERY_2026-11-01.md).

## Качество отзывов и отправка сводки

`demand` теперь сохраняет ID и версию отзыва. R7/R30/R90 — записи доступной RSS-
выборки (в том числе редактирования), не установки. Жалобы после даты выпуска и
отзывы с совпадающей строкой версии считаются отдельно. Если RSS был собран до
нового выпуска, требуется новый срез: ротационная разведка теперь допускает его
раньше семидневного cooldown. Порядок направлений меняется по дням; это не случайный
контроль исследования. Прежним записям ID/версия задним числом не заполняются.

`quality_metrics.py` → `docs/data_quality.json`: полнота текущих запросов, свежесть,
лимиты выдачи, охват/усечение RSS и неизвестные версии. Успешный запрос и низкая
доля ответов с лимитом не означают охват всех приложений или измеренный спрос.
В калькуляторе CLI вклад требует явно заданного `--acquisition-cost` (в том числе
0 для сценария органики); условный страновой CPI не подставляется как факт.

Ручной Actions `mode=report` отправляет один текущий сводный поисковый отчёт по
обеим веткам и сохраняет API message_id в артефакте. Этот режим не запускает скан
и не отправляет другие PENDING-события. Локальный preview без отправки:

```bash
python3 send_report.py --event-key preview --out /tmp/report-preview.json
```
