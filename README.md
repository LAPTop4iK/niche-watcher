# Niche Scanner + Playbook

Система поиска ниш вида «инкумбент сдал позиции, спрос остался» для стратегии:
взять лидера ниши → разобрать механики → собрать своё приложение лучше/симпатичнее → играть на цене.

Состав:
- `scanner.py` — автоматический сканер App Store по ключевым словам (iTunes Search API, stdlib, без ключей)
- `charts_scan.py` — скан ТОП-чартов по жанрам через официальные RSS: ищет **категории**, где лидеры устарели
- `play_scan.py` — тот же зомби-скан для Google Play (`pip3 install --user google-play-scraper`)
- `reviews.py` — свежие отзывы любого приложения через RSS (майнинг фич-гэпов и подтверждение живого спроса)
- `seed_queries.json` — категории-кандидаты и поисковые запросы
- `.github/workflows/scan.yml` — ежедневный автозапуск в GitHub Actions + алерты в Telegram
- `niches.db` (SQLite) — снапшоты: история оценок и версий → velocity между прогонами
- `report.md` / `charts_report.md` — отчёты последнего прогона

---

## 1. Почему это работает (факты на октябрь 2026)

«Конвейер зомби» поддерживается платформами систематически:

| Событие | Дата | Эффект |
|---|---|---|
| Google Play: existing apps должны target API 35 | 31.08.2026 (прошёл) | Не дотянувшие **скрываются для новых юзеров** на новых Android |
| Google Play: новые апдейты — target API 36 | 31.08.2026 (прошёл) | Обновить без поднятия API нельзя |
| Apple: все аплоады — Xcode 26 / iOS 26 SDK | 28.04.2026 (прошёл) | Не пересобравшийся разработчик **не может выпускать обновления** |
| Google «zombie crackdown» | июль 2024 | Массовые делистинги неактивных приложений |

Разработчик-одиночка пропускает дедлайн → теряет возможность обновляться →
приложение продолжает висеть на органике поиска и рекламе, рейтинг «работает по инерции»
(Apple больше не показывает дату обновления на карточке в iOS). Окно живёт от месяцев до пары лет.

## 2. Быстрый старт

```bash
# локально
python3 scanner.py                                  # полный прогон (~70 запросов × 4 гео, ~6 мин)
python3 scanner.py --categories construction --countries us   # узкий прогон

# автоматика: создай ПРИВАТНЫЙ репозиторий из этой папки
git init && git add -A && git commit -m "niche scanner" && git push   # на GitHub
# в Settings → Secrets → Actions добавь TG_BOT_TOKEN и TG_CHAT_ID (опционально)
# workflow сам сканит ежедневно в 06:17 UTC, коммитит niches.db и шлёт алерты о НОВЫХ зомби
```

Velocity (прирост оценок за 30 дней) начинает считаться со второго прогона, проведённого ≥7 дней спустя.
Первый прогон: velocity = n/a — это нормально.

## 3. Бесплатные заменители платных сервисов (проверено живьём, октябрь 2026)

| Платный сервис | Что даёт | Бесплатная замена | Статус |
|---|---|---|---|
| Sensor Tower / data.ai | выручка, загрузки, топы | **RSS-чарты Apple** (`itunes.apple.com/<гео>/rss/topfreeapplications|topgrossingapplications/limit=200/genre=<id>/json`) — официальный, без ключа, работает | ✅ проверено |
| Sensor Tower public pages | оценки по конкретному приложению | публичные страницы sensortower.com/app-info/... для крупных приложений + Wayback Machine на них; для мелких — эвристика ratings-velocity × eCPM | ⚠️ частично |
| AppMagic | загрузки/выручка | AppMagic free tier (дневной лимит запросов) | ✅ |
| ASO-платформы (AppTweak, ASOdesk) | частотности ключей, позиции | ASOMobile (16 free-инструментов), Appfigures free; Apple Search Ads popularity endpoint **умер** (проверено: пусто без авторизации), suggest-endpoint App Store **умер** (404) | ⚠️ |
| Майнинг отзывов (ReviewBot и т.п.) | свежие отзывы | **RSS отзывов** `itunes.apple.com/<гео>/rss/customerreviews/id=<id>/sortby=mostrecent/json` — официальный, с датами | ✅ проверено |
| Данные Google Play (AppBrain и т.п.) | updated, installs, отзывы | **google-play-scraper** (python, без зависимостей): `app()` → `updated`, `installs`, `ratings`; `reviews()`; `similar()` | ✅ проверено |
| Делистинги-мониторы | кто вылетел из сторов | Pixalate monthly delisted-apps reports (бесплатно, вручную раз в месяц) | ✅ |
| Проверка аккаунтов разработчиков | портфельность продавца | iTunes Search API `lookup?id=<artistId>&entity=software` — все приложения продавца сразу | ✅ |

Ключевой вывод: ~90% нужных данных лежат в двух официальных бесплатных источниках —
iTunes Search/Lookup API + RSS (чарты и отзывы) и google-play-scraper. Это и есть скелет системы.

## 4. Telegram-алерты: настройка (5 минут)

Сканер сам шлёт уведомления о **новых** зомби (тех, что не флагались в прошлых прогонах).
Чтобы это заработало:

1. В Telegram найди **@BotFather** → `/newbot` → имя → получишь **токен** вида `123456789:AAH...`. Токен = полный доступ к боту, никому не показывай.
2. Напиши своему боту любое сообщение (так он узнает твой чат).
3. Открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` → найди `"chat":{"id": 123456789}` — это **chat_id**.
4. GitHub-репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:
   - `TG_BOT_TOKEN` = токен из шага 1
   - `TG_CHAT_ID` = chat_id из шага 3
5. Для локальных запусков: `export TG_BOT_TOKEN=... TG_CHAT_ID=...` перед `python3 scanner.py`.

Зачем секреты, а не файл в репо: Actions-раннер — безголовая среда, забрать алерт можно только
через API бота, а секреты GitHub не попадают в код и в логи. Утёкший токен = кто-то читает твои
алерты и шлёт свои.

## 5. Алгоритм (7 шагов)

1. **Категории-кандидаты.** Критерии: вечная задача (не хайп), аудитория близка к деньгам/профессии,
   исторически делается одиночками. См. `seed_queries.json`. Форумный слой идей: Reddit `r/<ниша>`
   («is there an app that…»), 4PDA, профильные форумы, FB-группы.
2. **Массовый скан** (автоматизирован): iTunes Search API по категориям и гео.
3. **Фильтр зомби:** версия старше 18 мес И оценок ≥ 500 (пороги в флагах).
4. **Проверка, что спрос жив, а не умер вместе с приложением:**
   - velocity > 0 (оценки прибавляются при мёртвой версии — главный сигнал);
   - Google Trends 5 лет: flat/сезонный, не плавный спад;
   - свежие отзывы на карточке при старой версии.
5. **Майнинг отзывов лидера:** 30–50 свежих 1–2★ = причина распада + фич-лист для MVP.
6. **Ключи:** руками в сторе по 10–15 запросам ниши — зомби держит #1–5 → позиции перехватываются
   точным вхождением в название/подзаголовок. Частотности: ASOMobile (free), Appfigures (free), AppMagic (free tier).
7. **Buy vs build:** убывающие приложения на Flippa/Acquire продаются за 12–20× месячной прибыли —
   покупка оправдана, когда покупаешь активы (скачивания, рейтинг, позиции), а не код.

### Скоринг (в сканере, 0–100)

| Компонент | Вес | Логика |
|---|---|---|
| Возраст версии | 35 | 36 мес без обновлений = максимум |
| Масса аудитории | 30 | log-шкала, 100k оценок = максимум |
| Velocity | 25 | +50 оценок/мес у зомби = максимум; нет данных = 10 (нейтрально) |
| Итог | 100 | Смотри в отчёте; вручную добавь: Google Trends, отзывы, портфельность продавца |

**Внимание на портфельных продавцов:** если у `sellerName` десятки однотипных приложений
(например, Calc Hub, LLC) — зомби может быть осознанной «дойкой», и они проснутся. Проверяй
остальные приложения продавца перед go.

### Go/No-Go (≥6 из 8 зелёных)

- [ ] версия инкумбента > 18 мес, velocity > 0
- [ ] Google Trends flat/сезонный
- [ ] свежие отзывы о поломках («не запускается на iOS 18»)
- [ ] зомби держит #1–5 по ншевым ключам
- [ ] гео с высоким eCPM (US/UK/DE) или готовность платить
- [ ] фич-гэп закрывается соло за 1–2 месяца
- [ ] продавец не портфельная сеть
- [ ] риск заветирования фичи площадкой минимален

## 6. Разбор лидера (5 слоёв) + правовые рамки

Цель разбора — механики, вайб и монетизация, а НЕ код. Идеи/механики/цены не защищены,
код/ассеты/дизайн 1:1 — защищены.

| Слой | Как | Что даёт |
|---|---|---|
| Поведенческий | Пользуешься сам, записываешь флоу, скриншотишь каждый экран, ведёшь фич-матрицу | Карта UX, онбординг, вайб |
| Метаданные стора | Карточка, скриншоты, What's New за все версии, In-App Purchases список | Монетизационная модель, история позиционирования |
| Отзывный | Апмайнинг 1–2★ и 5★ свежих | Гэпы, ожидания, цена перехода |
| Сетевой | mitmproxy/Charles на СВОЁМ устройстве и СВОЁМ аккаунте — читаешь свои же запросы | Структура API, телеметрия, аналитика (Amplitude/Mixpanel-стек) |
| Статический (IPA) | Только поверхностно, см. ниже | SDK-стек, права, локализации, строки |

Статический разбор IPA, который ты легально получил (своё устройство, свой бэкап), — рабочая практика:
- `Info.plist` + entitlements → карта возможностей (push, health, Siri, виджеты…);
- встроенные frameworks → SDK-стек: реклама (AdMob/AppLovin), аналитика, покупки (RevenueCat?) —
  это прямая подсказка по монетизации;
- файлы локализаций (`.strings/.stringsdict`, xcstrings) → все фичи как на ладони, часто ещё и
  список языков = план локализации;
- строки-литералы → названия фич, URL эндпоинтов, названия экранов.

**Нельзя:** снимать FairPlay-шифрование с App Store сборки (антиобход DMCA §1201 / аналоги),
копировать код, ассеты, иконки, тексты и дизайн 1:1, дёргать чужой бэкенд автоматизацией.
**Можно:** изучать поведение, метаданные, свои же сетевые запросы, состав SDK, механики и цены —
и переизобретать лучше «в чистой комнате». В этом ZCode есть встроенный реверс-тулкит (REA) для
статического анализа Mach-O/IPA — достаточно положить файл в воркспейс.

## 7. Мульти-рыночная модель: конфиг, формулы, выбор монетизации

**24 рынка в конфиге**, каждый с языком запросов, eCPM, affinity (готовность платить), CPI и
тиром сканирования. Три файла образуют гибкий конфиг:

- **`markets.json`** — профиль каждого рынка: язык запросов, eCPM (interstitial/rewarded, iOS),
  готовность платить за разовые приложения (paid_affinity 1–5), зрелость подписок (sub_affinity),
  ориентир CPI, комиссия стора + `_defaults_research` (конверсии RevenueCat 2026, churn, retention).
  Все числа — редактируемые дефолты; обновляй своими фактическими данными по мере запусков.
- **`seed_queries.json`** — запросы по языковым группам (`en/de/fr/ja/ko/zh-TW/ru`);
  сканер сам берёт локализованный набор для каждого гео (fallback на en).
- **`revenue_model.py`** — формулы и сравнение моделей:

```
ADS:   RPD_ads  = eCPM/1000 × impressions_per_DAU × активные_дни (d1+d7+d30)
PAID:  RPD_paid = hardpaywall_conv × price × (1−комиссия)   conv ×= affinity/3
SUB:   LTV_sub  = trial_conv × price × (1/churn) × (1−комиссия)   conv ×= affinity/3
HYBRID = доля×RPD_ads + (1−доля)×LTV_sub
Break-even CPI = RPD (ads/paid) или LTV (sub) — платный трафик выше этого = убыток
```

Бенчмарки в дефолтах (см. sources в markets.json): freemium-подписка конвертит 1,7% установок
за 30 дней (топ-квартиль 4,2%), **hard-paywall — 10,7%** (в 5 раз выше freemium) — [RevenueCat
State of Subscription Apps 2026](https://www.revenuecat.com/blog/growth/app-engagement-metrics-subscription-apps);
eCPM Tier-1: interstitial iOS ~$8–14, rewarded $15–30, топ-рынки interstitial — [JP/US/TW (TopOn Q4-2025)](https://anymindgroup.com/report/download-ecpm-trends-interstitial-rewarded-ads-2025);
CPI утилит iOS ~$1–3 в Tier-1 ([Business of Apps CPI](https://www.businessofapps.com/ads/cpi/research/cost-per-install)).

### Карта рынков: где деньги и где аномалии (`python3 revenue_model.py --model rank`)

Два показателя: **абсолютная выручка** (сила рынка) и **индекс аномалии** = выручка лучшей
модели / CPI (рычаг органики — сколько денег приносит доллар трафика или бесплатная установка).

| Сегмент | Рынки | Что делать |
|---|---|---|
| Деньги-максимум (tier 1, ежедневный скан) | us, jp, gb, au, ca, de, tw | основная охота за зомби |
| Аномалия «богатые малые рынки» (tier 2) | ch, no, dk, se, fi, at | de/скандинавские/финская локализации = почти нет конкуренции, богатые юзеры, paid affinity 4/5 |
| Аномалия «религиозные подписки» (tier 2) | sa, ae (+ il) | prayer/qibla/zakat/hijri — живые подписки при дешёвом трафике; подтверждено сканом: зомби-чётки с 2,2k оценок и 5,5 годами без обновлений |
| Аномалия «язык-монополия» (tier 2) | il (иврит), fi, no, dk | RTL и редкие языки — одна качественная локализация занимает категорию целиком |
| Мульти-гео бонус | tw → hk, de → ch/at, en → au/ca/ie/nz/sg | одно приложение с одной локализацией закрывает несколько рынков |
| Тренировка/портфель (tier 2) | ru, kr | чарты RU прогнили (вход лёгкий), но eCPM мизерный — без UA-бюджета |
| Единственный рынок, где платная покупка бьёт подписку | **jp** | hard-paywall конверсия ~18% с affinity 5 |

Стратегия одного релиза: делаешь качественное приложение → локализуешь en+de+ja (+скандинавский
или арабский по нише) → оно автоматически продаётся в 10–15 экономиках из таблицы.

Дефолтные выводы модели (`python3 revenue_model.py --geo us,jp,de,ru`):

| Рынок | Лучшая модель | Почему |
|---|---|---|
| **US/GB** | подписка (гибрид второй) | sub_affinity 5, высокий eCPM; каннибализация подписками минимальна |
| **JP** | **разовая покупка/пейволл** | hard-paywall конверсия ~18% с affinity 5 — уникальная культура платных утилит; подписки в утилитах слабые |
| **DE/TW** | подписка, но платная покупка почти равна | affinity paid 4 → paywall-стратегия валидна |
| **RU** | всё слабое в деньгах; годится портфель-ads и тренировка | eCPM ~$1,5, чарты прогнили (вход лёгкий, денег мало) |

Дерево решений по типу приложения:

- **Инструмент «расчёт/конвертация»** (одноразовая ценность) → JP/DE: пейволл или разовая покупка;
  US: lifetime-покупка внутри freemium.
- **Трекер/журнал** (повторная ценность: кормления, финансы, тренировки) → подписка везде, кроме JP.
- **Видео/аудио утилиты** (телесуфлёр, метроном, тюнер) → US/GB подписка, JP разовая покупка.
- **Массовая широкая аудитория с низкой ценностью визита** → реклама, но только гео с eCPM ≥ $8
  (US/GB/DE); в RU/Tier-2 реклама имеет смысл только как портфельная стратегия без UA-бюджета.

Проверка гипотезы деньгами (без colossal-труда): MVP 2–6 недель → soft-launch на органике
(ASO по зомби-ключам) → первый платный трафик малым бюджетом ($100–300) → сравнить фактический
RPD/LTV с моделью → масштабировать или закрыть. CPI из markets.json — ориентир для этого теста.

## 8. Рутина мониторинга

**Ежедневно (автомат, GitHub Actions):** `scanner.py` по всем категориям и гео, алерты о новых
зомби в Telegram, коммит БД (velocity копится).
**Еженедельно (45 мин):**
- `python3 charts_scan.py --countries us,de,gb,ru` — свежий chart-decay: какие **категории**
  прогнили (это источники новых ниш, о которых ты не знал);
- `python3 play_scan.py --countries us,de` — Play-зомби по тем же категориям;
- для топ-5 зомби из отчёта: `python3 reviews.py <id>` — жив ли спрос (свежие отзывы?) и что
  сломалось (1–2★); Google Trends руками; `lookup` по artistId — портфельность продавца.
**Ежемесячно (1–2 ч):** отчёт Pixalate по делистингам (освободившиеся места), пересмотр
seed-категорий (форумные ленты: Reddit «is there an app that», 4PDA, профильные форумы),
сверка порогов, просмотр Go/No-Go по накопленным кандидатам.
**Перед каждым go:** полный чек-лист из раздела 5 + портфельность продавца + Buy-vs-Build.

## 9. Аналоги: что берём, что они упускают (доказано на наших данных)

**Конкуренты-сервисы:** Sensor Tower (в мае 2026 поглотил AppMagic как инди-решение), AppTweak,
appfigures, MobileAction, ASOMobile, AppFollow. Их неуязвимые сильные стороны: точные оценки
выручки/загрузок (94% точность рангов у Sensor Tower), ad-intelligence (Pathmatics), полная
история ключей. Это их бизнес — соревноваться там не нужно.

**Что аналоги упускают (наши краники), с доказательствами:**

1. **«Гнилость» инкумбента как первичный фильтр.** У аналогов «gap» = разрыв в keyword-метаданных;
   возраст версии и падение поддержки они не фильтруют. Доказательство: в нашей базе (3 800+
   приложений) медианный возраст зомби — 62,8 мес; 27–33% приложений в keyword-длинном хвосте
   гнилые против 3–13% в топ-чартах → decay-сигнал в платных инструментах не является измерением
   поиска ниш, у нас это ядро.
2. **Ошибка выжившего у аналогов.** Платные сервисы ранжируют видимых лидеров чартов; деньги
   органического длинного хвоста им не видны. Наши две таблицы выше — прямое измерение этого разрыва.
3. **Цена.** 90% наших данных — официальные бесплатные источники (Search API, RSS-чарты, RSS
   отзывов, google-play-scraper, граф «You Might Also Like»). Аналоги продают similar-apps
   и отзывы подписчикам.
4. **Портфельный аудит и свежесть отзывов в отчёте из коробки.** Доказательство пользы: в базе
   уже видны сети (Tim O's Studios — 11 приложений, Phan Nhat Đang — 14) — их «зомби» могут
   проснуться; одиночка с одним гнилым приложением — идеальная цель.
5. **Кластерный decay** (`similar_crawl.py`): 31% соседей Calculator for iPad по «You Might
   Also Like» тоже гнилые — ниша гниёт кластерами, и граф ловит ниши, которые нельзя назвать
   ключевым словом.

**Что популярно в 2026 и как это покрыто формулами (без ошибок выжившего):**

- **Вайбкодинг: 7× рост запусков приложений, но приложения до 2020 года генерируют 69%
  подписочной выручки** (RevenueCat 2026) — деньги лежат у старых инкумбентов, т.е. ровно там,
  куда смотрит наш сканер. Конкуренция снизу растёт → наши фильтры velocity + свежесть отзывов
  отделяют живой спрос от мёртвого.
- **AI-приложения: +41% выручки на платящего, но churn +30% быстрее** → для категории `ai_tools`
  подними `monthly_churn_utility` в markets.json до 0.09–0.10 и смело ставь цену выше.
- **Триалы 17+ дней конвертят на 70% лучше** → в MVP дефолтный триал ≥ 17 дней, не 3–7.
- **Платформенные поверхности** (виджеты, watch, lock screen) — дешёвый буст конверсии и
  фичеринг-элиджибилити → категория `widgets_watch` добавлена в сканер.
- **Методика исключает ошибку выжившего структурно**: мы ищем не успешные приложения (их
  изучают все аналоги), а заброшенные с живым спросом — выборка смещена ПРОТИВ выживших,
  и это фича, а не баг.

Полный список источников данных системы — в таблице раздела 3.

## 10. Heat: рост конкуренции в нише (декей — это не всё)

Зомби% отвечает «открыто ли окно», heat отвечает «не закрывается ли оно уже кем-то другим».
В отчёте — секция Heat по категориям: fresh% (доля приложений с версией младше 12 мес),
new (сколько приложений увидели впервые за прогон — приток в нишу).

Матрица решений (зомби% × fresh%):

| | fresh% низкий | fresh% высокий |
|---|---|---|
| **зомби% высокий** | 🟢 свободная ниша: окно открыто, конкурентов нет | 🟡 ниша уже поднимают: скорость решает, заходить только если можешь лучше |
| **зомби% низкий** | 🔵 рынок зрелый, инкумбенты живые: нужен другой заход (цена/фича/гео) | 🔴 рынок обслужен, нужен новый угол |

`new` за несколько прогонов = приток: если каждые 2 недели в нише +10 новых приложений —
кто-то уже discovers её (возможно, такой же сканер у конкурента). Время решает.

## 11. Native-риск: смерть боли vs смерть поддержки

⛔натив-флаг в отчёте = пересечение с нативными фичами iOS (калькулятор, фонарик, уровень,
сканер, компас, Measure, Magnifier). Framework разбора:

1. **Смерть поддержки** (боль жива, разработчик устал) → возможность. Сигнал: свежие отзывы,
   velocity > 0.
2. **Смерть боли** (ОС поглотила функцию) → ловушка. Сигнал: нативный флаг + отзывы только
   ретроспективные + velocity падает.

Кейс Calculator for iPad (61k оценок, 6 лет гнили, отзыв за сент. 2026, свежих за 60 дней — 1):
спрос через поиск в сторе ещё течёт, но боль частично поглощена (нативный Calculator на iPad +
Math Notes с iPadOS 18). Вердикт: голый клон = мёртвая затея; вход возможен только отстройкой —
Apple Pencil-воркфлоу (расчёты на полях чертежа), гэпы Math Notes (экспорт, проф. единицы,
автономность), отсутствие рекламы как ценность. У Concrete Calculator Plus (⛔натив по слову
calculator) боль НЕ поглощена — бетона в iOS нет, поэтому это чистая «смерть поддержки».

Правило: ⛔натив = не авто-отказ, а обязательный вопрос «решает ли ОС эту боль?» Фонарик — да
(скип). Бетонный расчёт — нет (окно открыто). Калькулятор на iPad — наполовину (нужна отстрой).

## 12. Добыча новых ниш: seed_harvester.py

Публичные страницы платных сервисов закрыты (проверено 30.10.2026: appfigures — Cloudflare 403,
Sensor Tower — 404, topappcharts — 404). Обходить — нельзя и незачем: у нас уже есть данные.

`python3 seed_harvester.py` майнит собственную базу: частотные биграммы названий приложений,
которых ещё нет в seed — кандидаты в новые запросы/категории. Первым прогоном найдено:
`mileage tracker` (×10), `driving theory test` (×11), `meal planner` (×15), `budget planner`
(×8), `book tracker` (×7). Раз в месяц прогоняй — добавляй достойных в seed_queries.json.

Дополнительные легальные источники категорий/рынков: бесплатные отчёты самих платников
(Sensor Tower blog, AppMagic reports, MobileAction ASO-2026, RevenueCat report) — они публикуют
топы категорий и рост ниш именно для маркетинга, читай и переноси в seed.

## 13. Инфраструктура наблюдателя: Pages + Telegram без VPS

**VPS не нужен вообще.** Архитектура целиком живёт на бесплатном GitHub:

- **Ежедневный скан** — Actions runner (cron 06:17 UTC), tier-1 рынки;
- **Алерты** — Telegram API это исходящий HTTPS-вызов из раннера: бот отправляет сообщения
  без сервера, слушающего порт. VPS нужен только для интерактивных ботов (webhook/polling),
  нам это не требуется. Настройка токена — раздел 4;
- **Веб-дашборд** — `dashboard.py` строит 4 чарта (матрица декей×heat, топ-зомби, приток в ниши,
  аномалии рынков) и `index.html`; workflow-джоба `deploy-pages` публикует на **GitHub Pages**:
  Settings → Pages → Source: GitHub Actions. URL: `https://<юзер>.github.io/<репо>/`;
- **База** — niches.db коммитится после каждого прогона = longitudinal-история
  (динамика короткая = velocity между прогонами, длинная = приток/отток ниш за месяцы).

**Локальный флоу:** прогон → отчёт → дашборд → `git add -A && git commit` → спросить
«пушим?» → push. Сессия ZCode может выполнять это по шагам и спрашивать перед push.

## 14. Веб-рынок: тот же арбитраж, другая поверхность

Декей-арбитраж работает и на вебе — там старение даже агрессивнее (техстек виден мгновенно,
SEO-позиции стареют медленнее продукта). Где искать:

- **Заброшенные utility-сайты с живым SEO-трафиком**: конвертеры, калькуляторы, генераторы
  на jQuery-стеке, топ-3 в Google, дизайн 2015-го, обвешанные рекламой. Прямое доказательство
  спроса: такие сайты продаются на Flippa/BidLol (пример: concrete-calculators.com).
  Метрики: позиция в Google по коммерческому ключу + возраст дизайна (Wayback) + AdSense-плотность.
- **Инструменты без API/автоматизации**: спрос есть (форумы просят), предложение не даёт.
- **Сайты без мобильной версии** в нишах, где трафик мобильный.
- **Категории, которые Google-поиск обслуживает плохо**: калькуляторы со специфическими
  юрисдикциями (налоги конкретной страны), локальные нормативы.

Экономика та же: AdSense/аффилиатка вместо eCPM-сетки, SEO вместо ASO, «лучше/симпатичнее/
быстрее» вместо фич-гэпа. Слабое место веба против приложения: нет push-удержания и иконки
на телефоне — зато нет ревью Apple, 15% комиссии и зомби-дедлайнов платформ.

Источники детекции: Ahrefs free keyword generator, Google autocomplete, Wayback Machine
(дизайн-возраст), Flippa/Acquire контентные листинги, «is there a tool that» на Reddit,
профильные форумы. Ищи те же формулы: спрос стабилен, инкумбент стар, подражателей мало.

## 15. Валидность метрик: известные искажения и что перенять у аналогов

Аудит формул на ложные корреляции (проведён 31.10.2026, часть багов найдена и исправлена живьём):

**Что уже поймано и починено:**
- Geo-gap: iTunes-поиск втягивает нерелевантных гигантов в длинные запросы (Capital One Mobile
  как «лидер» по «frost dates») → добавлен фильтр токен-пересечения. Остаточный шум: родовые
  токены (calculator/tracker) пропускают гигантов смежных ниш — перед go смотреть глазами.
- ⛔натив-список: изначально содержал «concrete» (бетона в iOS нет!) — убрано.

**Смещения, которые надо помнить (не баги, а свойства):**
1. **Inflow раздувается расширением seed.** `new` в Heat = впервые увиденные; когда добавляем
   запросы/гео — всплеск new ≠ рост ниши. Валидны только тренды при фиксированном seed
   (сравнивай прогоны одной версии seed_queries.json).
2. **Малые выборки tier-2.** 6 приложений в выборке — 17% зомби это 1 штука. Матрица режет
   n<8; Heat-таблицу читать с оглядкой на «Видно».
3. **Ошибка выжившего работает НАМ на пользу.** Делистнутые зомби невидимы → наш zombie%
   недооценивает гниль (консервативная оценка, не переоценивает возможность).
4. **rating_count кумулятивен** — это историческая аудитория, не текущий спрос. Текущий
   спрос = velocity + свежесть отзывов (для этого они в отчёте).
5. **Apple батчит отзывы** — velocity скачет; смотреть тренд по 2–3 прогонам.
6. **Search API отдаёт топ-50 релевантности** — мы видим верх ниши, не весь рынок; zombie%
   = «среди видимых».
7. **affinity-множители в revenue_model — гипотезы до первой калибровки.** После своего
   первого релиза подставь фактические конверсии в markets.json — модель станет твоей.

**Что переняли у аналогов/индустрии:**
- **downloads ≈ ratings × 40** (диапазон 20–100: ~20–30 у приложений с агрессивным промптом
  отзыва, 100+ у чисто органических) — стандартный эстиматор индустрии; используем для
  перевода наших rating_count в объёмы. Категорийный коэффициент калибруем по своим данным.
- **Триалы 17+ дней** (RevenueCat) — в MVP по умолчанию.
- **Практика вендоров сверять свои модели с App Store Connect** — у нас то же самое:
  после первого релиза сверяем предсказание модели с фактом и правим markets.json.

**Что сознательно НЕ перенимаем:**
- Точечные оценки выручки платников для малых/средних приложений: их модели дают ±5–25%
  только на крупных (у топ-1% паблишеров 94% всей выручки стора — панели заточены под них),
  на малых ошибка «в разы». Наша зона (зомби-длинный хвост) — их худшая зона. Хватает
  ratings×40 × RPD-модели.
- Keyword-difficulty как главный фильтр ниши: метаданные конкурента ≠ сила продукта.
- Топ-чарты как витрина поиска ниш: доказано нашей базой — там 3–13% зомби против 27–33%
  в keyword-длинном хвосте.

**Geo-gap (geo_gap.py) — региональный арбитраж:** лидер 2000+ оценок в гео A при вакууме
(<300) в гео B той же языковой группы. Пример из первого прогона: Goodreads-класс «book
tracker» — 760k в US против 68–152 в AU/GB; «moon phase hunting» — 118k US против ~50 AU/GB.
Важно: отсутствие аналога ≠ наличие спроса — кандидата проверяем Google Trends + форумами
перед go.
